## 2. Ringkasan Dasar Teori
Data Manipulation Language (DML) merupakan sekumpulan perintah SQL yang digunakan untuk mengelola data di dalam tabel (`INSERT`, `UPDATE`, `DELETE`, dan `SELECT`). Karena adanya batasan kunci tamu (*foreign key*), manipulasi data harus memperhatikan hierarki relasi: tabel induk (*parent*) seperti `buku`, `anggota`, dan `petugas` harus diisi terlebih dahulu sebelum tabel anak seperti `peminjaman` dan `detail_peminjaman`.

Untuk menjaga integritas data, MariaDB menyediakan variabel `sql_safe_updates` yang jika diaktifkan akan menolak operasi `UPDATE` atau `DELETE` tanpa klausa `WHERE` yang memanfaatkan kolom kunci. Pengujian basis data wajib dilakukan secara berpasangan antara uji positif (memastikan masukan valid berhasil disimpan) dan uji negatif (memastikan data yang melanggar constraint ditolak server dengan kode galat yang sesuai).

### 3.2 Uji Mode Aman (sql_safe_updates)
Menjalankan perintah pembaharuan tanpa syarat kunci saat mode aman aktif:

```sql
SET SESSION sql_safe_updates = 1;

-- Ditolak oleh server karena tidak ada WHERE dengan kolom kunci
UPDATE buku SET stok_buku = stok_buku + 1;
-- ERROR 1175 (HY000): You are using safe update mode and you tried to update a table without a WHERE that uses a KEY column

-- Diterima karena menggunakan kolom kunci (id_buku > 0)
UPDATE buku SET stok_buku = stok_buku + 1 
WHERE tahun_terbit >= 2022 AND id_buku > 0;
```

## 4. Jawaban Titik Analisis

* **Titik Analisis 1:**  
  Penggunaan `INSERT ... SELECT` pada detail peminjaman lebih andal daripada memasukkan nilai manual karena memastikan konsistensi relasi dan integritas data referensi buku yang dipinjam. Jika terjadi perubahan data pada tabel induk, riwayat transaksi pada detail peminjaman tetap merekam snapshot data yang valid pada saat transaksi itu dicatat.

* **Titik Analisis 2:**  
  Penghapusan data buku yang sedang terikat dalam transaksi peminjaman aktif akan ditolak oleh server (`ERROR 1451`) akibat adanya batasan kunci tamu (`FOREIGN KEY` dengan `RESTRICT`). Jika data referensi perpustakaan perlu dibersihkan, pendekatan yang benar adalah melakukan pengarsipan atau menonaktifkan status buku alih-alih menghapus baris data secara fisik dari basis data.

* **Titik Analisis 3:**  
  Constraint `CHECK` pada tabel `buku` (`stok_buku >= 0`) hanya memvalidasi batasan nilai pada kolom tabel tersebut secara mandiri. Constraint ini tidak secara otomatis mencegah peminjaman melebihi stok saat transaksi dibuat jika validasi stok lintas tabel belum diatur melalui stored procedure atau trigger (menjadi utang desain yang akan diselesaikan pada modul transaksi berikutnya).

## 5. Hasil Latihan dan Modifikasi

### 5.1 Pengarsipan Anggota Non-Aktif
```sql
-- Membuat tabel arsip struktur serupa
CREATE TABLE IF NOT EXISTS anggota_arsip LIKE anggota;

-- Pindahkan data anggota non-aktif yang mendaftar sebelum 2025 dan belum pernah meminjam
INSERT INTO anggota_arsip 
SELECT a.* FROM anggota a
LEFT JOIN peminjaman p ON a.id_anggota = p.id_anggota
WHERE a.status_anggota = 'nonaktif' 
  AND a.tgl_daftar < '2025-01-01'
  AND p.id_peminjaman IS NULL;

-- Hapus dari tabel utama
DELETE FROM anggota 
WHERE status_anggota = 'nonaktif' 
  AND tgl_daftar < '2025-01-01'
  AND id_anggota NOT IN (SELECT id_anggota FROM peminjaman WHERE id_anggota IS NOT NULL);
```

### 5.2 Pemeliharaan Data Buku
```sql
-- Menyesuaikan tahun terbit atau menambah stok buku referensi tertentu dengan aman
UPDATE buku 
SET stok_buku = stok_buku + 2 
WHERE tahun_terbit < 2022 AND id_buku > 0;
```

## 7. Pembahasan dan Kendala

* **Kendala yang Ditemui:**  
  Saat melakukan perintah `UPDATE` massal pada tabel `buku`, server mengeluarkan peringatan `ERROR 1175` karena variabel mode aman aktif tanpa menyertakan kolom kunci primer di klausa `WHERE`.
* **Cara Mengatasi:**  
  Menambahkan filter tambahan pada klausa `WHERE` seperti `AND id_buku > 0` agar sistem mendeteksi penggunaan kolom berindeks, sehingga perintah pembaharuan dapat dieksekusi dengan aman.
